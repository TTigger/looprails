# Rule: Code style

- Formatting is automated (see the `post-edit-format` hook); do not hand-fight the formatter.
- Names state intent; avoid abbreviations that need a glossary.
- Keep files small and single-purpose; when a file outgrows one responsibility, split it.
- Prefer pure functions and explicit data flow over hidden state.
- Comments explain WHY, not WHAT. Delete commented-out code rather than parking it.
